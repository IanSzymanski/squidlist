# Local storage contracts

Issue #6 defines `Squidlist.Storage.Contracts`. Interfaces expose only .NET,
Core, and Storage types; Windows adapters can implement them without changing
Core. There are no filesystem, database, picker, or playback implementations here.

## Responsibilities

| Contract | Owns | Does not own |
| --- | --- | --- |
| `IMediaRootStore` | Root configuration, marker validation/creation, identity-checked rebinding | Folder-picker UI, media moves or deletion |
| `ICatalogStore` | Loading and atomic replacement of the #7 catalog snapshot | Scanning, fingerprints, matching, ID assignment |
| `IPlaylistStore` | Listing handles and loading, creating, replacing, deleting #9 playlist files | Media deletion, display-name uniqueness, playlist editing UI |
| `IMediaScanner` | Streaming supported-file discoveries and per-file/subtree failures | Metadata extraction (#19), catalog reconciliation (#11), writes |
| `IPlaybackStateStore` | One saved `PlaybackSession` per root containing state and queue | Playback, media resolution, removing unavailable IDs |

Stores receive an explicit root so a configuration change cannot silently redirect
an in-flight operation to another library. Implementations validate root availability
and marker ownership for each operation. A Core `Configured` state alone is not
proof of filesystem existence. Root-store Get reports Missing(null) for no setup,
Missing(path) for unavailable configured paths, and Invalid for invalid configuration
or markers. Operational access failures are exceptions rather than an empty root.
Successful Configure returns Configured; successful Rebind returns Moved.
Rebinding validates the previously persisted root identity, never path equality alone.

Catalog and playlist models come from issues #7 and #9. Playlist handles are
nonblank, opaque strings generated by the implementation and scoped to one root.
They remain stable across root rebinding and document/name edits. A copied file
may receive a new handle. Implementations reject invalid handles with
ArgumentException and must never interpret arbitrary caller strings as unrestricted
paths. Listing includes corrupt files so a caller can load each handle separately
and show failures without losing the remaining list. Returned lists are detached,
read-only snapshots. An absent playlist directory in a valid root lists as empty.

## Ownership and concurrency

Callers retain ownership of supplied snapshots. Implementations must not mutate
them or return live mutable views. The composing application owns service lifetime;
an implementation needing disposal can implement IDisposable/IAsyncDisposable and
be disposed by its owner. Individual operations own and release their streams,
database handles, and enumerators; these never cross the interfaces.

The caller serializes mutations and complete read/modify/write sequences per root;
these contracts do not provide optimistic concurrency or multi-process coordination.
Reads overlapping a save see the old or new complete snapshot, never a partial one.
Create never overwrites an existing playlist. Save replaces an existing playlist
only; Delete never touches referenced media. Catalog and session saves are upserts.
Multi-store transactions are not promised.

## Absence, failure, and cancellation

- Null Load means no saved artifact; empty catalogs/playlists are valid artifacts.
  Corruption, unsupported versions, access denial, and unavailable roots must never
  be converted to null or silently repaired by overwriting data.
- Invalid arguments raise ArgumentException (including ArgumentNullException).
  Operational failures raise StorageException with a StorageFailure code. Adapters
  translate platform IO and parser exceptions, retaining diagnostic inner exceptions.
  Messages may include paths or technical details; UI maps codes to user-facing copy.
- UnsupportedVersion includes an unknown persisted format version; CorruptData
  includes malformed JSON or invalid model data. Conflict includes incompatible
  root markers. Missing playlist Save is NotFound. Delete of an absent file succeeds.
- Every operation accepts cancellation. A canceled token before work starts yields
  OperationCanceledException with that token, not StorageException. Implementations
  check cancellation during long-running work and do not block the UI thread.
- Before the mutation commit point, cancellation leaves the previous logical state
  intact (temporary files may require cleanup). Once committed, return success even
  if cancellation arrives afterward; never report cancellation for a committed write.
  Interrupted atomic writes preserve a readable old or new artifact. Storage failures
  can have an uncertain outcome; callers reload before retrying destructive operations.

## Scan coverage and playback sessions

Scans traverse supported media beneath the root, yielding relative locations.
Unsupported files are ignored. Implementations must constrain traversal at symlinks
and reparse points rather than escaping the root. Per-item/subtree errors yield
`MediaScanEvent.Failed` and traversal continues where possible. A root-wide failure
throws. Consumers can count events for progress; no known total or ordering is
promised. Stop or dispose enumeration to cancel further discovery and release resources.

Any failure event, cancellation, exception, or early disposal makes the scan
incomplete. Reconciliation must not infer deletion from absence in that scan;
inaccessible subtrees must not make existing media appear deleted. Scanning never
allocates MediaId values; reconciliation owns stable identity decisions.

PlaybackSession groups PlaybackState and PlaybackQueue into one immutable save
unit so position and queue cannot be restored from different writes. Current media
need not be in the queue. Missing media IDs, repeated queued IDs, order, and shuffle
state survive load without resolution. An absent session lets the caller choose
default playback state and an empty queue. A present empty current media ID is invalid.

## Implementation follow-ups

#8 implements catalog persistence, #13 playback persistence, and #16–18 Windows
root selection/markers/enumeration. Concrete adapters must test cancellation around
commit points, interrupted writes, corrupt/versioned reads, per-item scan failures,
and root/handle confinement. Interface declarations alone do not prove those runtime
guarantees. No backend or network dependency is introduced by these contracts.
